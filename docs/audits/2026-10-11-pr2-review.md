## Controles críticos revisados

- Las rutas de IA autentican con `getUser`, rechazan usuarios anónimos y orígenes ajenos. Los privilegios de operador dependen de `app_metadata`, no del editable `user_metadata`.
- La base controla el plan de publicación y límites 1/5/10; no acepta un upgrade por `planVisual` enviado por navegador. La lectura pública aplica el plan efectivo y oculta publicaciones excedentes, conservando borradores y QR de respaldo.
- Reservas y ledger usan bloqueo por propietario, identificador único, devolución única y estados terminales inmutables. Los resultados inciertos requieren conciliación: no se debe devolver saldo o repetir llamadas sin conocer el resultado.
- La conexión PostgreSQL limita el proyecto esperado y verifica TLS. El rol runtime no es superusuario ni bypassrls. La aplicación sigue siendo la frontera de aislamiento entre propietarios para las tablas privadas accesibles a runtime.
- Pedidos test no conceden planes ni créditos. Un cliente que comunica un pago no puede activarse; el operador necesita un contrato o una recarga registrados. La existencia del justificante en la base no sustituye verificar el pago bancario.
- El presupuesto IA es una reserva estimada en base de datos, no un límite contractual de facturación del proveedor. Validar coste real y límites en la cuenta del proveedor antes de habilitarlo.

Están registradas `commercial_accounts_credits`, `mvp_runtime_access`, `ai_regeneration_policy`, `customer_checkout`, `storage_campaign_path` y `paddle_sandbox`, además de las migraciones de documentación. Las funciones privadas de créditos no son ejecutables por anon/authenticated; runtime tiene las firmas necesarias. Las funciones de página/QR públicas son deliberadamente accesibles.

**Riesgo de despliegue reproducible:** el historial remoto y los archivos locales tienen versiones diferentes para las mismas migraciones. Ejemplo: `commercial_accounts_credits` remoto `20261010085531`, archivo `20261009212242`; `ai_regeneration_policy` remoto `20261010105915`, archivo `20261010102819`. Antes de ejecutar un push automático de migraciones, comparar sus contenidos y reconciliar el historial. No volver a aplicar los CREATE de tablas, roles o columnas ya existentes ni reparar versiones sin comprobar equivalencia. Las pruebas de una base limpia no detectan este problema de upgrade.

Los advisors reportan avisos de SECURITY DEFINER en `innova_public_page` e `innova_resolve_qr`: son intencionales para la proyección pública y resolución QR, con search_path fijo y comprobación de visibilidad. No justifican revocar esos endpoints indiscriminadamente. Los avisos INFO de RLS sin políticas en tablas ERP pueden representar denegación por defecto; no equivalen a fuga pública.
